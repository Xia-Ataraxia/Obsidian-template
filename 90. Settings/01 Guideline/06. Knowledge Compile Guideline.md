## Overview

Karpathy LLM Knowledge Base 패턴에 기반한 볼트 전체 지식 컴파일 규칙을 정의한다. 채택자가 `/obsidian-vault-compile` 스킬을 설치한 경우 그 스킬로 아래 처리를 수행할 수 있다. 스킬이 없으면 이 문서의 워크플로를 허용된 도구로 직접 따른다.

```
Knowledge Compile
├── Layer 1 — Raw Sources (`85. Raw/`, 읽기 전용 · Book/Paper/Eagle 은 80. References)
├── Layer 2 — Wiki (LLM 소유)
│   ├── 01 Wiki/ — 종합 레이어 (Enhanced MOC, 도메인 개요)
│   └── 02 Terminologies/ — 원자적 엔티티 (append-only)
├── Layer 3 — Schema (규칙 문서)
└── Workflow — Target → Compile → Index → Report → Spot-check
```

- [llm-wiki · GitHub](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 에서 영감을 받았다.

## Map

### Three-Layer Architecture

볼트의 지식 컴파일은 3 개 레이어로 구성한다.

#### Layer 1 — Raw Sources (읽기 전용)

compile 의 **입력 = `85. Raw`** 하위 원문 (collector 무관).

| 소스 타입 | 관측 위치 |
|---|---|
| 아티클 | `85. Raw/01 Articles` |
| 영상 raw | `85. Raw/02 Videos` |
| 웹 클리핑 | `85. Raw/03 Clippings` (`03 Github` 와 번호 중복 — 관측명 유지) |
| GitHub 원문 | `85. Raw/03 Github` |
| Threads | `85. Raw/04 Threads` |
| 뉴스레터 | `85. Raw/05 Newsletters` |
| YouTube 원문 | `85. Raw/06 YouTube` |
| X | `85. Raw/07 X` |
| 메일 | `85. Raw/15 Mail` |
| KakaoTalk | `85. Raw/16 KakaoTalk` |
| 책·논문·Eagle | `80. References/01 Book` · `02 Paper` · `06 Eagle` (서지/이미지 레퍼런스, compile 입력 원문 아님) |

- 컴파일 에이전트는 소스 본문을 읽되, **내용을 변경하지 않는다** (`85. Raw`는 `status` 외 불변).
- 허용되는 수정: `status` 필드 변경뿐. **wikilink 는 raw 본문이 아니라 위키 페이지(`50. AI/01 Wiki`)에 삽입**한다.
- 소스 파일은 **불변 원본 (source of truth)** 으로 취급한다.

#### Layer 2 — Wiki (LLM 소유)

LLM 이 생성하고 유지보수하는 지식 산출물이다. 두 영역으로 구성한다.

**01 Wiki/ — 종합 레이어**

`50. AI/01 Wiki/` 에 Enhanced MOC, 도메인 개요, 비교, 타임라인 등 종합 페이지를 배치한다.

- Flat 구조를 유지한다. 서브폴더를 생성하지 않는다.
- 모든 파일에 `type: wiki`, `created_by: agent`, `authorship: agent` 를 포함한다.
- `index.md` — Wiki 페이지 카탈로그. 에이전트가 탐색 시 첫 진입점으로 사용한다.
- `log.md` — 컴파일 활동의 append-only 기록.

**02 Terminologies/ — 원자적 엔티티**

`50. AI/02 Terminologies/` 의 개별 용어 노트는 원자적 개념 정의를 담는다.

- 컴파일 시 새 소스에서 발견된 정보를 기존 용어 노트에 **append** 한다.
- 기존 내용을 수정하거나 삭제하지 않는다.
- 새 용어 노트를 생성하지 않는다. 캐시에 있는 기존 용어만 연결한다.

#### Layer 3 — Schema

컴파일 동작을 제어하는 규칙 문서이다.

- the runtime's skill directory — compile 스킬이 설치된 경우 그 실행 명세
- `90. Settings/01 Guideline/` — 볼트 가이드라인
- `AGENTS.md` — 에이전트 행동 지침

### Compile Workflow

채택자가 `/obsidian-vault-compile` 스킬을 설치한 경우 그 스킬을 실행하면 아래 순서로 처리한다. 없으면 같은 순서를 허용된 도구로 직접 따른다.

#### Phase 0 — Term Cache 구축

`02 Terminologies/` 의 모든 `type: terminology` 파일에서 파일명과 aliases 를 추출하여 로컬 Term Cache(예: `/tmp/vault-compile-terms.txt`)에 둔다. 캐시 경로는 설치된 compile 도구가 정한다.

#### Phase 1 — Target 선택

`85. Raw/` 하위에서 `status: todo` 인 파일을 수집한다.

- `--type` 으로 소스 타입을 필터링한다.
- `--date` 로 `date_created` 를 필터링한다 (기본값: 오늘).
- `--backfill` 사용 시 날짜 필터를 무시하고 모든 `status: todo` 를 대상으로 한다.
- 본문이 50 단어 미만인 파일은 건너뛴다.

#### Phase 2 — Compile (병렬 Sonnet 에이전트)

대상 파일을 `--batch-size` (기본 5) 단위로 분할하여 sonnet 에이전트에게 배분한다.

각 소스 파일에 대해 에이전트가 수행하는 작업:

| Step | 작업 | 대상 |
|---|---|---|
| 1 | **소스 읽기** | `85. Raw` 소스 파일 전체 (불변) |
| 2 | **합성 + 용어 링킹** | `01 Wiki/` **위키 페이지에** 개념/엔티티 추출·합성하며 `[[wikilink]]` 삽입 (raw 본문 불변) |
| 3 | **용어 노트 갱신** | `02 Terminologies/` 기존 용어에 새 맥락 append (신규 파일 생성 금지) |
| 4 | **Wiki 도메인 페이지** | `01 Wiki/` 도메인 페이지 생성 또는 갱신 |
| 5 | **완료 마킹** | raw frontmatter `status: todo` → `status: done` |

#### Phase 3 — Index & Log 갱신

메인 에이전트가 직접 수행한다.

- `01 Wiki/index.md` — 신규/갱신된 Wiki 페이지를 카탈로그에 반영한다.
- `01 Wiki/log.md` — 컴파일 기록을 append 한다.

Log 엔트리 형식:

```markdown
## [YYYY-MM-DD] compile | N sources processed
- 처리된 소스: [[Source 1]], [[Source 2]], ...
- Wiki 생성: [[New Wiki Page]]
- Wiki 갱신: [[Existing Wiki Page]]
- 용어 링크 추가: N개
```

#### Phase 4 — Report

전체 처리 결과를 요약 보고한다.

#### Phase 5 — Spot-check

별도 verifier 에이전트가 무작위 3 개 파일을 검증한다. wikilink 무결성, frontmatter 보존, Wiki 형식 준수를 확인한다.

### Wiki Enhanced MOC 규격

`01 Wiki/` 의 각 페이지는 아래 구조를 따른다.

```yaml
---
aliases: []
created_by: agent
authorship: agent
date_created: YYYY-MM-DD
date_modified: YYYY-MM-DD
type: wiki
tags:
  - ai-generated
---
```

```markdown
# {Domain Name}
> {N} sources | Last updated: {date} | Gaps: {missing topics}

## Core Concept
{도메인의 핵심 개념 1-2문장}

## References
- [[Source Note]] — {핵심 기여 한 줄 요약}

## Terminology Bridge
- [[Term]] — {이 도메인에서의 역할}

## Connections
- [[Related Wiki Page]] — {관계 설명}

## Gaps
- {소스가 없는 중요 하위 주제}
```

- **References**: 소스 노트 wikilink + 한 줄 요약. 새 소스 발견 시 append 한다.
- **Terminology Bridge**: `02 Terminologies/` 용어와의 연결. 도메인에서 해당 용어가 어떤 역할인지 명시한다.
- **Connections**: 다른 Wiki 페이지와의 관계.
- **Gaps**: 소스가 부족한 하위 주제. 에이전트가 자동 식별하여 기록한다.

### 용어 노트 갱신 규칙

컴파일 시 `02 Terminologies/` 의 관련 용어 노트에 새 소스 정보를 추가한다.

- `## Sources` 섹션에 한 줄씩 append 한다:

	```markdown
  ## Sources
  - [[Source Note]] — {이 소스에서 발견된 맥락 한 줄 요약}
  ```

- `## Sources` 섹션이 없으면 파일 끝에 생성한다.
- 기존 섹션 (`## Core Concept` 등) 의 내용을 수정하지 않는다.
- 이미 등록된 소스는 중복 추가하지 않는다.

### Index 규격

`01 Wiki/index.md` 는 Wiki 레이어의 전체 카탈로그이다.

```markdown
---
aliases: []
created_by: agent
authorship: agent
date_created: YYYY-MM-DD
date_modified: YYYY-MM-DD
type: wiki
tags:
  - ai-generated
---

# Wiki Index
> {N} pages | Last updated: {date}

## By Domain
- [[Domain Page]] — {한 줄 설명} ({source count} sources)
```

- 도메인별로 알파벳/가나다순 정렬한다.
- 컴파일 실행 시마다 자동 갱신한다.
- 에이전트는 Wiki 탐색 시 이 파일을 첫 진입점으로 사용한다.

### Navigation: MOC Vs Wiki

`03 MoC/` (인간 MOC) 와 `01 Wiki/` (AI Wiki) 는 **완전 독립**이다.

| 속성 | 03 MoC/ | 01 Wiki/ |
|---|---|---|
| 작성자 | 인간 | AI |
| `type` | `moc` | `wiki` |
| 용도 | 인간이 큐레이션한 지식 허브 | AI 에이전트용 탐색 카탈로그 |
| 상호 링크 | 하지 않는다 | 하지 않는다 |

두 시스템 모두 `02 Terminologies/` · `85. Raw`(raw 소스) · `80. References/01·02`(서지 소스) 로의 wikilink 를 공유한다.

### Type Adapter

소스 타입별로 읽기/추출 전략이 다르다. 어댑터 패턴으로 확장한다.

| 타입 | 읽기 대상 | 추출 항목 | 특수 처리 | 상태 |
|---|---|---|---|---|
| `video` | transcript body | 토픽, 개념, 기술 용어 | 단락 분리 | 구현됨 |
| `article` | 본문 전체 | 핵심 주장, 인용, 데이터 포인트 | — | 향후 |
| `book` | 하이라이트/노트 | 핵심 개념, 인용구 | — | 향후 |
| `paper` | abstract + 노트 | 연구 질문, 방법론, 발견 | — | 향후 |

새 타입 추가 시 이 테이블과 SKILL.md 의 Agent Prompt Template 을 함께 갱신한다.

### Authorship 규칙

| 위치 | `created_by` | `authorship` |
|---|---|---|
| `01 Wiki/` 전체 | `agent` | `agent` |
| `02 Terminologies/` (AI 갱신 시) | 기존 유지 | 기존 유지. user-authored 노트는 승인 후 `mixed` |
| `85. Raw` (raw 소스) | 기존 유지 | 변경하지 않는다 (`status` 외 본문 불변) |
| `80. References/01 Book·02 Paper` (서지 소스) | 기존 유지 | 변경하지 않는다 |

raw 소스(`85. Raw`)는 본문 불변이므로 wikilink 를 삽입하지 않는다 — 링킹은 위키 페이지 쪽에서만 한다. 서지 소스(`80. References/01·02`)도 `created_by`/`authorship` 을 바꾸지 않는다. compile 의 산출 링크는 전부 `50. AI/01 Wiki` 페이지에 모인다.

## Rules

- Layer 1 (Raw Sources, `85. Raw`) 은 불변이다. 허용되는 수정은 `status` 필드 변경뿐이다. wikilink 는 raw 본문이 아니라 위키 페이지(`50. AI/01 Wiki`)에 삽입한다. 단락 분리·본문 재작성 금지.
- Layer 2 용어 노트는 append-only 이다. 기존 내용을 수정하거나 삭제하지 않는다.
- 컴파일 에이전트는 새 용어 노트를 생성하지 않는다. Term Cache 에 있는 기존 용어만 연결한다.
- Wiki 페이지는 **합성(synthesis)** 이다 — compile 에이전트는 `85. Raw`의 raw를 읽어 개념/엔티티를 추출하고 위키 페이지를 생성한다. 합성은 `50. AI/01 Wiki` 에만 쓰며 사람 권위 합성(`40. Permanent Notes`)을 침범하지 않는다.
- 컴파일 에이전트는 반드시 sonnet 모델을 사용한다. Haiku 는 사용하지 않는다.
- 파일 처리는 순수 의미 이해 (semantic understanding) 로만 수행한다. Python 스크립트, 정규식, 문자열 매칭을 사용하지 않는다.

## Caveats

### 합성 (Synthesis)

compile 에이전트는 `85. Raw`의 raw를 읽어 개념/엔티티를 추출하고 **위키 페이지를 합성·생성**한다(wikilink 포함). 단:

- **AI 합성은 `50. AI/01 Wiki` 에만** 쓴다. 사람 권위 합성(`40. Permanent Notes/`)은 별개의 평행 레이어이며 AI 가 침범하지 않는다.
- 두 레이어는 공유 용어/레퍼런스 링크로만 연결된다.
- 합성은 의미 이해(semantic) 기반이며, Python 스크립트/정규식으로 만들지 않는다.

```markdown
## Core Concept
# 허용 — compile 의 합성 (50. AI/01 Wiki)
Attention Mechanism은 입력 시퀀스의 각 위치가 다른 위치를 가중 참조하는 메커니즘으로,
Transformer가 장거리 의존성을 병렬로 포착하게 하는 핵심 구성요소다.

# 사람 권위 합성은 여전히 40. Permanent Notes 에서 (AI write 금지)
```

### Wiki 도메인 중복 방지

새 Enhanced MOC 생성 전 반드시 `01 Wiki/` 를 glob 하여 유사 도메인이 없는지 확인한다. "Attention Mechanism" 과 "Self-Attention" 이 별도 페이지로 존재하면 안 된다.

### 용어 노트 신규 생성 금지

컴파일 에이전트는 `02 Terminologies/` 에 새 파일을 생성하지 않는다. Term Cache 에 있는 기존 용어만 연결한다. 새 용어가 필요하면 채택자가 `/terminology` 스킬을 설치한 경우에만 그 스킬을 사용한다.

### Haiku 에이전트 사용 금지

컴파일 에이전트는 반드시 sonnet 모델을 사용한다. Haiku 는 wikilink 오류, 허위 보고, 스크립트 생성 등의 문제가 확인되었다.

### 스크립트/정규식 사용 금지

파일 처리는 순수 의미 이해 (semantic understanding) 로만 수행한다. Python 스크립트, 정규식, 문자열 매칭을 사용하지 않는다.
