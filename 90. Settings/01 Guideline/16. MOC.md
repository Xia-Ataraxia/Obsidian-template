## Overview

MOC는 **노트를 통해 관계와 맥락을 만들고, 다시 찾아갈 길을 남기는 지도**다. 폴더 분류와는 별개다.

- **차용한 개념**
	- [Linking Your Thinking](https://www.linkingyourthinking.com)에서 제안하는 Maps of Content를 차용했다.
- **이 볼트의 운영 규칙**
	- 번호·Tier·dual-MOC 한도·도메인/역할 축은 이 볼트의 자체 규칙이다. 원 제안자의 보편 규칙으로 취급하지 않는다.
- **책임 구분**
	- 이 문서는 관계를 선택하고 연결하는 방법을 다룬다.
	- 물리적 위치는 [[01. Folders and Placement]], `moc` 필드의 기록 형식은 [[02. Properties]]가 담당한다.
	- `16`은 정렬 번호이며 정책 우선순위가 아니다.
- **작성 기준**
	- [[00. Guideline Authoring]]과 [[guideline.template]]을 따른다.

```text
MOC
├── 관계 축 — 노트를 통한 맥락과 탐색
├── 작업 순서 — Gathering → Collide → Navigate / Coda
├── 멤버십 — 선택한 관계이지 임의 백링크가 아님
├── Dual-Axis — 도메인(100–800)과 역할(900)
├── Dual-MOC — 서로 다른 축, 최대 2개
├── Tier — 0 / 1 / 2 번호와 부모 연결
└── 위치 — 파일 트리는 Folders, 계층은 노트 링크
```

## Map

### 관계 축

- **MOC는 노트가 다른 노트와 맺는 관계다.**
	- 같은 주제의 생각·질문·자료·산출물을 한 지도에서 조망한다.
	- 폴더 트리의 하위 칸이 아니며, 태그와도 다른 축이다.
- **관계는 폴더를 가로지를 수 있다.**
	- Permanent Note와 Literature Note가 같은 MOC에 연결될 수 있다.
	- 멤버십 때문에 노트를 옮기거나 복사하지 않는다. 물리 위치는 [[01. Folders and Placement]]만 따른다.
- **임의 백링크가 멤버십은 아니다.**
	- 본문 언급, `related`, 우연한 역링크는 탐색 실마리일 수 있다.
	- 멤버십은 해당 MOC를 맥락으로 **선택한** 관계다. 필드에 어떻게 적는지는 [[02. Properties]]를 따른다.

### 작업 순서

- **관련 노트를 한 작업대에 모은다 (Gathering).**
	- 미리 완벽한 분류를 요구하지 않는다. 같은 주제에 닿는 링크를 먼저 올린다.
- **모인 아이디어를 부딪히게 한다 (Collide).**
	- 무엇이 중심에 오고 무엇이 옆에 붙는지, 근접성과 연결 강도를 가린다.
- **다시 들어올 길을 남긴다 (Navigate).**
	- 미래의 내가 어디서 시작할지 보이게 한다. 설명 백과사전보다 재진입이 우선이다.
- **한 사이클을 닫는다 (Coda).**
	- 지금 보이는 구조와 다음에 이을 자리를 짧게 남기고, 지도는 노트와 함께 자라게 둔다.

### 멤버십과 선택

- **실제로 쓰는 맥락의 MOC만 고른다.**
	- 더 구체적인 Tier 2가 있으면 Tier 1 대신 Tier 2를 쓴다.
	- Permanent Note는 Tier 0(📖)을 직접 쓰지 않는다. Tier 1 이하를 쓴다.
- **프로젝트 노트는 MOC 멤버십 없이 둔다.**
	- 폴더와 `type`으로 자리가 충분하면 `moc`를 비운다.
- **새 MOC가 필요하면 부모와 기존 번호를 확인한 뒤 만든다.**
	- 번호 없는 standalone MOC는 두지 않는다. 번호를 붙이고 부모에 연결한다.

### Dual-Axis

계층은 서로 다른 두 질문으로 나눈다. 같은 상위 주제를 다루더라도 이론·분야와 실무 역할은 별개 관계다.

| 축 | 범위 | 질문 | 예시 |
| --- | --- | --- | --- |
| 도메인 | 100–800 | 이 지식은 어떤 분야인가? | AI, PKM, Finance |
| 역할 | 900 | 이 지식은 어떤 역할에서 쓰이는가? | Programmer, Researcher |

- **두 축이 겹치는 노트는 dual-moc로 양쪽에 연결한다.**
	- 같은 축에서 두 개를 고르지 않는다.
- **100→900 번호는 나로부터의 거리를 따른다.**

```text
100 Themes ─── 외부 지식/주제 (가장 먼 것)
200 Habitus ── 체화된 습관/성향
300 Literature ── 참고 자료
400 Data ───── 데이터
500 Tools ──── 도구
600 Methodologies ── 방법론
800 Outputs ── 내 생산물
900 Persona ── 나 자신 (가장 가까운 것)
```

- **새 Tier 0은 이 스펙트럼의 빈자리에만 둔다.**
	- 현재 Tier 0은 8개로 고정한다: 100, 200, 300, 400, 500, 600, 800, 900.

| 도메인 MOC | 역할 MOC | 도메인 scope | 역할 scope |
| --- | --- | --- | --- |
| [[102.03 AI]] | [[📚 901 Programmer]] | AI/ML 이론, 모델, 기법 | SW 설계, 테스트, 도구, 성장 |
| [[📚 202 Psychological]] | [[📚 907 固有]] | 심리학 이론, 프레임워크 | 개인 정체성 내러티브, 자기 성찰 |
| [[101.03 Knowledge Management]] | [[📚 902 Personal Knowledge Management Specialist]] | PKM 방법론, 도구 | 지식 큐레이터 역할 수행, 실천 기준 |

- **각 MOC 노트 본문 맨 위에 scope 경계를 적는다.**

```markdown
> [!info] Scope
> 이 MOC 는 [도메인/역할] **[핵심 키워드]** 를 다룬다.
> [대비 영역]은 [[대비 MOC]] 에서 다룬다.
```

### Dual-MOC

`moc`에 복수 값을 쓸 수 있다. 무엇을 고를지는 이 문서가, 어떻게 적을지는 [[02. Properties]]가 담당한다. 한도는 최대 2개다.

| 노트 유형 | moc 값 개수 | 조합 |
| --- | --- | --- |
| Terminology / Article / Paper | 2 | 유형 MOC + 도메인 MOC |
| 도메인-역할 겹침 노트 | 2 | 도메인 MOC + 역할 MOC |
| 일반 Permanent Note | 1 | 도메인 MOC |
| Project Note | 0 | folder + type으로 충분 |

```yaml
# Terminology: 유형 + 도메인
moc:
  - "[[📚 104 Terminologies]]"
  - "[[102.03 AI]]"

# 도메인-역할 겹침
moc:
  - "[[102.03 AI]]"
  - "[[📚 901 Programmer]]"

# 일반
moc: "[[206.01 Finance]]"
```

### Tier와 번호

관계의 넓이는 3단계로 좁힌다. 살아 있는 Tier 1·2 이름은 이 문서의 목록이 아니라 `03 MoC/`의 노트다.

| Tier | Icon | 번호 형식 | 역할 | 예시 |
| --- | --- | --- | --- | --- |
| 0 | 📖 | `x00` | 최상위 도메인 | [[📖 200 Habitus]] |
| 1 | 📚 | `x0x` | 도메인 하위 분류 | [[📚 202 Psychological]] |
| 2 | — | `xxx.xx` | 세부 주제 | [[202.01 무기력]] |

| 번호 | MOC 노트 | 영역 |
| --- | --- | --- |
| 100 | [[📖 100 Themes]] | 외부 관심사, 주제, 변수, 용어 |
| 200 | [[📖 200 Habitus]] | 체화된 자본 (심리, 사회, 신체, 언어, 경제, 문화, 영적) |
| 300 | [[📖 300 Literature]] | 참고 자료 (책, 논문, 사례, 영상) |
| 400 | [[📖 400 Data]] | 데이터 |
| 500 | [[📖 500 Tools]] | 도구, 소프트웨어, 하드웨어 |
| 600 | [[📖 600 Methodologies]] | 방법론, 프롬프트, 스크립트, 지표 |
| 800 | [[📖 800 Outputs]] | 생산물 (블로그, 유튜브, 프로그램, 직무) |
| 900 | [[📖 900 Persona]] | 역할 정체성 (프로그래머, PKM, 인디해커, 연구자 등) |

- **새 MOC는 부모 Tier의 마지막 번호 + 1을 쓴다.**
	- 파일명: `번호 이름.md` (예: `204.07 Scent Management.md`).
	- Tier 0/1은 아이콘을 붙인다: `📖`, `📚`. Tier 2는 번호만 쓴다.
	- Tier 1은 부모 Tier 0 아래, Tier 2는 부모 Tier 1 아래에 연결한다. Tier 2는 `부모번호.순번`이다.
- **부모 연결은 `up`과 `moc`가 같은 부모를 가리키게 한다.**
	- Tier 0의 `up`은 비운다.
	- 필드 인코딩은 [[02. Properties]]를 따른다.

```yaml
type: moc
up: "[[부모 MOC]]"
moc: "[[부모 MOC]]"
tags:
  - moc
```

### 파일 위치

- **MOC 노트의 자리는 파일 트리다.**
	- 위치·flat 배치는 [[01. Folders and Placement]]를 따른다.
	- 계층은 하위 폴더가 아니라 부모 링크다.

## Rules

- 저장 전에 지도에서 실제로 관련 노트에 다시 진입할 수 있는지 확인한다.
	- [[16. MOC#작업 순서]]에 따라 모은 링크의 맥락과 읽는 순서를 검토한다.
- 관계 선택과 표기 형식을 각각 확인한다.
	- 연결 대상·개수·축은 [[16. MOC#멤버십과 선택]]과 [[16. MOC#Dual-MOC]]를 따른다.
	- 번호·부모 연결은 [[16. MOC#Tier와 번호]], 필드 인코딩은 [[02. Properties]]를 따른다.
- 관계를 정리하면서 파일을 불필요하게 옮기거나 복제하지 않았는지 확인한다.
	- 파일 위치는 [[01. Folders and Placement]]를 따른다.

## Caveats

### 폴더와 혼동

MOC에 속한다고 해서 그 노트를 `03 MoC/`나 주제 폴더로 모으지 않는다. 지도는 링크이고, 파일 자리는 하나다.

### 임의 백링크

어떤 노트가 MOC를 언급했다는 것만으로 멤버로 넣지 않는다. 맥락으로 선택한 관계만 멤버십이다.

### `moc` 값 3개 이상

값을 3개 이상 넣으면 기준이 흐려진다. 유형+도메인 또는 도메인+역할에서 최대 2개다.

### Tier 0 직접 연결

Permanent Note의 선택 값에 Tier 0(📖)을 직접 쓰지 않는다.

```yaml
# 피할 것
moc: "[[📖 200 Habitus]]"

# 대신 사용
moc: "[[📚 204 Bodily]]"
```

### 동일 축 중복

같은 축에서 2개를 고르지 않는다. dual-moc는 서로 다른 축의 조합이다.

```yaml
# 피할 것 — 같은 도메인 축 2개
moc:
  - "[[102.03 AI]]"
  - "[[📚 503 Programming]]"

# 대신 사용 — 도메인 + 역할
moc:
  - "[[102.03 AI]]"
  - "[[📚 901 Programmer]]"
```

### 번호 없는 MOC

번호가 없으면 번호를 부여하고 부모에 연결한다. Standalone MOC는 허용하지 않는다.

### 구 번호

`042`, `044`, `102.01-A` 같은 표기는 현행 멤버십이 아니다. 현재 번호는 `x0x`, `xxx.xx`다.
