## Overview

이 문서는 새 노트와 편집이 허용된 기존 본문을 읽기 쉽고 다시 찾기 쉽게 쓰는 개인 스타일이다. 원문 캡처를 예쁘게 고치거나 frontmatter·배치·권한·플러그인·템플릿 계약을 재정의하지 않는다. 작성은 [[00. Guideline Authoring]]과 [[guideline.template]]을 따른다.

글은 주장의 근거와 전제를 드러내고, 실제로 확인하거나 실행할 일을 구체적으로 쓰며, 독자가 생각의 흐름을 따라갈 수 있는 문장으로 구성한다.

```text
Writing Style
├── Structure & Navigation — 흐름과 제목
├── Clarity & Qualification — 목적·행동과 불확실성
├── Semantic Grouping — 문단·목록의 의미 단위
├── Quotation & Attribution — 인용·해석·내 말
├── Links & Evidence — 근거와 탐색 경로
└── Emphasis & Syntax — 강조와 Markdown 선택
```

## Map

### Structure & Navigation

- 노트의 흐름은 주제에 맞게 잡는다.
	- 예: `맥락 → 핵심 주장/관찰 → 해석 → 다음 행동`
	- 고정된 섹션명이나 순서를 강제하지 않는다.
- 제목은 독자가 다음 내용을 예측할 수 있게 쓴다.
	- 한 제목 아래에는 같은 질문이나 작업에 답하는 내용만 둔다.
- 관련 내용은 같은 문단에 묶는다.
	- 생각의 전환이나 탐색 단위가 생길 때만 새 heading을 만든다.
- 문장과 문단을 연결할 때는 응집성·일관성(cohesion and coherence)을 살핀다.
	- Cohesion은 표현과 문장 사이의 연결을, coherence는 글 전체에서 주장이 이어지는 논리적 흐름을 점검한다.
	- 앞에서 소개한 정보에 새 내용을 이어 붙이고, 인과·대조·예시 중 어떤 관계인지 드러낸다.
	- 핵심어 반복과 익숙한 정보에서 새로운 정보로 이어지는 배열은 [George Mason University의 글쓰기 지침](https://writingcenter.gmu.edu/writing-resources/general-writing-practices/cohesion-and-coherence)을 참고한다.
- 문장의 길이와 구조를 조절해 리듬을 만든다.
	- 짧은 문장은 핵심을 강조하고, 긴 문장은 조건과 생각의 관계를 풀어낸다.
	- [Sentence variety](https://owl.purdue.edu/owl/general_writing/academic_writing/sentence_variety/index.html)를 활용해 같은 길이·구조·도입어의 반복을 줄인다.
- 문서별 필수 제목·양식은 유지한다.

### Clarity & Qualification

- 독자가 이해하고 판단하는 데 필요한 표현을 고른다.
	- [Audience analysis와 user-centered writing](https://owl.purdue.edu/owl/subject_specific_writing/professional_technical_writing/audience_analysis/index.html)의 관점에서 독자의 배경지식과 읽는 목적에 맞춰 설명의 깊이를 정한다.
	- [Plain style](https://owl.purdue.edu/owl/general_writing/writing_style/plain_style%20.html)의 명료성·간결성·정확성을 따른다.
		- 전문 개념은 정확한 용어로 쓰고, 생소한 용어는 설명이나 참조로 이해를 돕는다.
- 주장의 근거와 그 근거에서 결론에 이르는 추론을 구분한다.
	- 관찰한 사실, 가정, 해석을 식별할 수 있게 쓰고, 결론을 바꿀 수 있는 반례와 대안을 검토한다.
- 목적이나 해야 할 행동이 있는 문단·항목은 첫 문장에 목적과 구체적인 행동을 먼저 쓴다.
	- 배경·근거·조건은 그 행동을 이해하는 데 필요한 만큼 뒤에 둔다.
- 누가 무엇을 하는지 보이도록 주어와 동사를 분명히 쓴다.
	- 추상 명사를 여러 개 겹치기보다 행위·판단을 동사로 적는다.
	- 행동이 명사화(nominalization)에 가려지면 동사로 풀어 쓴다.
		- [Purdue의 concision 지침](https://owl.purdue.edu/owl/general_writing/academic_writing/conciseness/changing_phrases.html)을 참고한다.
- 적용 범위와 조건은 처음 주장에 붙여 쓴다.
	- `~라는 뜻은 아니다`, `~라고 할 수 없다` 같은 방어 문장을 반복해 범위를 뒤늦게 수습하지 않는다.
- 제안·미확인 원인·확인 전 상태는 관련 문장 가까이에 한 번만 표시한다.
	- 같은 상태 고지를 뒤 문장마다 되풀이하지 않는다.
	- 확신의 강도는 근거에 맞춘다.
		- 학술 글쓰기의 [hedging](https://www.phrasebank.manchester.ac.uk/using-cautious-language/)처럼 필요한 유보를 두고, 관측한 대상·조건·범위를 주장에 포함한다.
- 불확실성과 결과에 영향을 줄 주의사항은 남긴다.
	- 위험을 적을 때는 확인할 신호·검사·다음 행동을 함께 적는다.
	- 의미를 바로잡거나 근거의 한계를 밝히거나 안전을 경고하는 부정문은 필요한 만큼 유지한다.

### Semantic Grouping

- 한 문단은 하나의 의미 단위로 쓴다.
	- 근거, 해석, 결론이 섞이면 문단을 나누고 관계를 짧게 표시한다.
- 순서·절차·행동은 목록으로 쓴다.
	- 생각의 관계를 풀어내는 논증은 문장과 문단으로 쓴다.
- 비교할 대상과 기준이 둘 이상이면 표를 쓴다.
	- 실행할 일·선택지는 bullet 또는 번호 목록으로 쓴다.
- 목록 항목은 한 가지 요점만 담아 간결하게 쓰고, 가능하면 한 문장으로 쓴다.
	- 같은 수준의 독립적인 주장·설명·행동은 병렬 구조의 항목으로 나눈다.
	- 부모 줄에는 링크·제목·주장만 남기고, 이유·조건·근거·설명·예시·이어지는 생각은 한 단계 아래 자식 bullet으로 내린다.
	- `—`·`:`·괄호로 부연을 같은 줄에 붙이지 않는다.
	- 부연이 둘 이상이면 자식 bullet을 나눠 각각 한 줄로 쓴다.
	- 두 문장을 길게 이어 붙여 한 항목으로 보이게 하여 이 원칙을 우회하지 않는다.
	- 논증이 길어지면 목록 대신 문단으로 쓴다.
	- 항목당 한 문장은 정보 계층을 드러내기 위한 이 볼트의 편집 선호다.
	- [Google Technical Writing의 Lists](https://developers.google.com/style/lists)는 가능한 한 병렬 구문·구조를 유지하고 목록 항목에 여러 문단을 둘 수 있다고 설명한다.
	- 들여쓰기 문자는 Emphasis & Syntax의 탭 규칙을 따른다.
- 모든 문장이나 항목을 각각 heading/bullet로 쪼개지 않는다.
	- 읽는 흐름을 끊을 정도의 과도한 세분화를 피한다.

#### Compact Before / After

출처나 인용을 가장하지 않는, 문단·행동 라벨 정리의 실제 Markdown 예다.

**Before**

```markdown
## 기능 메모
- 속도는 빠르다.
- 사용자가 좋아할 것 같다.
- 나중에 확인.
```

**After**

```markdown
## 기능 메모

속도는 빠르다. 사용자가 좋아하는지는 아직 확인하지 않았다.

**다음:** 사용자 3명에게 같은 과제를 요청하고 완료 시간을 비교한다.
```

### Quotation & Attribution

- 원문 인용, 해석, 내 말·결정은 서로 다른 문단 또는 짧은 라벨로 분리한다.
	- 라벨 예: `해석`, `내 말`, `결정`
- 인용은 실제 원문만 blockquote로 옮긴다.
	- 맞춤법·띄어쓰기·오탈자를 고치지 않는다.
	- 필요한 경우 원문 그대로임을 표시한다.
- 계획한 자기 발화는 `내 대사`로 표시해 원문 인용과 분리할 수 있다.
- 인용 바로 옆에 출처를 둔다.
	- 영상·음성은 timestamp, 문서는 page/section 등 확인 가능한 위치를 함께 적는다.
- 번역문은 `번역`으로 표시하고 원문 인용과 섞지 않는다.
	- 원문과 번역을 병기할 때도 각각 어느 쪽인지 분명히 한다.
- 출처 없는 문장을 인용처럼 꾸미거나, 내 해석을 원문 발화처럼 쓰지 않는다.

### Links & Evidence

- 용어 일관성(consistent terminology)을 지킨다.
	- 기존 terminology의 표제어와 의미를 확인하고 같은 개념에 같은 용어를 사용한다.
	- [Google Technical Writing의 Use terms consistently](https://developers.google.com/tech-writing/one/words#use-terms-consistently)를 따른다.
	- 약칭·번역어는 처음 소개할 때 대응을 밝힌다.
- 기존 terminology는 한 노트의 본문을 위에서 아래로 읽을 때 해당 개념의 첫 등장에 한 번 연결한다.
	- 실제 노트를 읽고 문맥과 의미가 맞는지 확인한 뒤 `[[표제어]]` 또는 `[[표제어|문맥에 맞는 표현]]`으로 쓴다.
	- 이후에는 용어를 유지하고 링크·정의는 반복하지 않는다.
	- 제목·frontmatter·코드·원문 인용은 그대로 두고, 링크할 수 있는 본문의 첫 등장을 기준으로 삼는다.
	- 기존 노트가 없으면 필요한 설명을 외부의 신뢰할 만한 자료에서 확인하고 출처를 연결한다.
	- 링크를 위해 새 terminology 노트를 자동으로 만들지 않는다.
	- 기존 설명을 연결하는 방법은 [Google의 Define new or unfamiliar terms](https://developers.google.com/tech-writing/one/words#define-new-or-unfamiliar-terms)를 참고한다.
	- 이 볼트에서는 반복 링크를 줄이기 위해 노트당 첫 등장 한 번을 적용한다.
- 전문 용어로 명명할 때는 분야의 실제 용례를 확인한다.
	- 대학 글쓰기 자료·학술 문헌·공식 스타일 가이드에서 명칭과 의미를 확인한다.
	- 직접 만든 설명용 이름은 제안으로 표시한다.
- Terminology 노트를 생성·수정할 때는 그 노트가 연결한 기존 이웃의 Related Concepts도 같은 작업에서 갱신한다.
	- 기존 노트의 편집 권한을 확인한 뒤 서로 연결하고, 권한이 없는 대상은 남은 갱신 항목으로 보고한다.
	- 용어의 근거는 권위 있는 1차 출처를 우선한다.
- 주장·수치·인용을 뒷받침하는 출처는 해당 문장이나 문단 바로 뒤에 둔다.
	- 근거를 문서 끝에만 모아 연결을 잃게 하지 않는다.
- 외부 URL은 백틱 코드가 아니라 클릭 가능한 Markdown 링크로 쓴다.
	- 링크 텍스트는 목적을 짧게 설명한다.
- 외부 이미지·영상 URL은 볼트에 내려받지 않고 원격 임베드를 우선한다.
	- 본문에는 `![설명](https://...)` 형태를 써서 미디어가 원격에 남게 한다.
	- 임베드만을 위해 로컬 이미지·영상 파일을 자동으로 만들거나 복사하지 않는다.
	- 로컬 보관본은 사용자가 명시한 요청이 있을 때만 둔다.
	- Obsidian이 지원하는 원격 임베드로 렌더할 수 없으면 클릭 가능한 Markdown 출처 링크를 남긴다.
	- 임의 영상 URL이 모두 렌더된다고 가정하지 않는다.
	- 이미 있는 로컬 첨부 파일은 건드리지 않는다.
- 볼트 안의 노트를 본문에서 참조할 때는 plain text나 백틱으로 감싼 파일 경로 대신 wikilink로 연결한다.
	- Agent-only reading pointers follow the conditional routing rules in [[03. Agent Permissions and Workflows#Context Discovery]] and do not prescribe `@` imports.
	- 노트 전체는 `[[노트제목]]`, 특정 정의나 규칙은 `[[노트제목#헤딩]]`으로 연결한다.
	- 템플릿 노트도 동일하게 연결한다.
	- 실행 명령·코드·도구 설정에서 실제 경로가 필요한 경우와 원문 인용은 그대로 유지한다.
- 문단 안에서는 참조하는 뜻을 담은 구절이나 문장 자체를 링크로 쓸 수 있다.
	- `[[노트제목|문장]]` 또는 `[[노트제목#헤딩|문장]]`으로 본문의 흐름과 출처를 함께 연결한다.
	- 별칭은 짧은 제목에 한정하지 않는다.
	- 단어·구절·문장 중 문맥에 자연스러운 표현을 쓴다.
	- 예: 노트를 편집할 때는 [[02. Properties#Authorship|작성 주체를 기록하는 규칙을 따른다]].
	- 링크 문장은 대상 노트가 실제로 뒷받침하는 의미여야 한다.
	- 내 해석을 원문의 규칙으로 보이게 연결하지 않는다.
- 다른 노트가 정의하는 내용을 참조할 때는 그 정의를 다시 복사하지 않는다.
	- 필요한 부분의 헤딩으로 연결하고, 현재 문단에는 이 문서에서 추가로 말하는 맥락만 적는다.
	- 실제 파일명과 헤딩을 확인한다.
	- 동명 노트 등 대상 구분이 필요한 경우에만 폴더 경로를 덧붙인다.
	- 본문 자체를 보여 줘야 하는 경우에는 임베드를 사용한다.
	- 단순한 근거·규칙 참조는 링크만으로 연결한다.
- 본문에 사람이 등장하면 해당 인물 노트의 wikilink로 감싼다.
	- 인물별 백링크가 쌓여 그 사람과 얽힌 기록이 한곳에서 역추적된다.
- 같은 노트에서 같은 사람이 여러 번 나오면 **첫 등장 한 번만** 링크하고 이후 언급은 plain text로 둔다.
	- 반복 링크는 백링크를 늘리지 않고 문장만 읽기 어렵게 만든다.
- 링크 대상은 인물 노트의 파일명(본명)이다.
	- 애칭·약칭으로 부를 때는 별칭 표기(`[[이름|별칭]]`)를 쓴다.
	- 아직 인물 노트가 없으면 본명을 확정할 수 있을 때만 링크한다.
	- 확인이 안 되면 plain text로 두었다가 노트를 만들 때 링크한다.
- 본문 날짜를 링크하는 규칙은 [[02. Properties#날짜 링크|날짜 링크 정책]]의 표와 예외를 그대로 따른다.
	- 이 문서는 그 계약을 복제하지 않는다.
- 날짜·인물 링크의 제외 대상은 같다.
	- 원문 인용, `85. Raw` 캡처 본문, 코드·URL 안의 표기는 그대로 둔다.
	- heading 안에는 링크를 넣지 않는다.
		- heading anchor가 깨진다.
	- frontmatter의 인물 표기는 [[02. Properties]]가 정한 `author`·`participants`·`speaker`·`owner` 등 지정 필드를 쓴다.

### Emphasis & Syntax

- 본문 중첩 목록은 깊이마다 실제 탭 문자(U+0009) 하나로 들여쓴다.
	- 공백 2칸·4칸으로 대체하거나 탭과 공백을 섞지 않는다.
	- 하위 항목의 이어지는 문단도 해당 목록 깊이에 맞춰 탭으로 정렬한다.
- 이 규칙은 Markdown 본문 목록에 적용한다.
	- YAML frontmatter는 [[02. Properties]]의 공백 2칸 규칙을 유지한다.
	- 코드 블록·원문 인용의 들여쓰기는 임의로 바꾸지 않는다.
- `#` H1은 제목 전용, 본문은 `##`부터 쓴다.
	- 계층 건너뛰기를 금지한다.
- Callout: `note`/`tip`/`warning`/`info`/`important`/`summary`/`abstract`.
- 코드 블록은 언어를 반드시 명시한다.
	- 없으면 `text`.
- 표는 헤더+구분자 행이 필수다.
- 굵게는 핵심 용어·결정·경고처럼 눈으로 훑어야 할 부분에만 선택적으로 쓴다.
	- 문장 전체를 굵게 만들지 않는다.
	- 닫는 강조 표기 뒤에 조사나 단어가 이어지면 공백을 둔다.
		- 예: `**종단 간 추적성** 을 확보한다.`
		- 공백은 표기 바깥에 두고, 강조할 내용과 여는·닫는 표기는 붙여 쓴다.
- 의미가 바뀌는 지점에는 빈 줄을 둔다.
	- 장식용 공백이나 빈 heading은 만들지 않는다.
- 행동 표시는 짧은 라벨로 시작해 한 번에 이해되게 쓴다.
	- 예: `**다음:**`, `**결정:**`, `**질문:**`

## Rules

- 저장 전에 직접 작성한 본문의 구조와 표현을 이 문서로 검토한다.
	- [[01. Folders and Placement]], [[02. Properties]], [[03. Agent Permissions and Workflows]], [[04. Applications and Integrations]], [[15. Templates]]의 계약을 재정의하지 않았는지 확인한다.
- 읽는 사람이 주장과 근거, 원문과 해석, 내 말과 다음 행동을 구분할 수 있는지 저장 전에 수동으로 검토한다.
- 출처가 있는 문장은 인용 위치와 링크를 확인한다.
	- URL·페이지·timestamp를 확인할 수 없으면 확인 전 상태를 정직하게 표시한다.
- 저장 후 본문 하위 목록에 공백 들여쓰기가 남지 않았는지, YAML에 탭이 들어가지 않았는지 원문으로 검증한다.
- Enforcement는 수동 review다.
	- 이 문서가 자동 formatter나 hook의 설치·실행을 의미하지 않는다.

## Caveats

- 이 문서는 별도의 정책 단계가 아니다.
	- 폴더·속성·권한·도구·템플릿 계약과 충돌하면 해당 문서를 따른다.
	- [[04. Applications and Integrations]]와 [[15. Templates]]는 같은 4단계이며, 이 문서는 그 아래의 작성 표현 규칙이다.
- `85. Raw`의 캡처 본문과 불변 기록인 기존 날짜 로그는 스타일 개선을 이유로 재작성하지 않는다.
- 템플릿 소스는 이 문서의 일괄 재서식 대상이 아니다.
	- 정해진 양식 안에서 새로 작성하는 본문에 적용한다.
- 원문 저장이 금지된 summary-only 대화 노트에는 인용 형식을 만들기 위해 transcript를 추가하지 않는다.
- 원문 인용은 항상 실제 출처의 문장을 그대로 보존한다.
	- `내 대사`로 표시한 계획 발화는 출처 인용과 명확히 구분해 별도로 표시한다.
- 보호된 `## Thinking`은 명시적 authorization 없이는 수정하거나 재배열하지 않는다.
- [[15. Templates]]의 engine syntax, required frame, placeholder와 exact task instructions는 이 스타일보다 우선한다.
- 스타일은 edit 권한을 주지 않으며 schema를 바꾸지 않는다.
	- 날짜 링크 규칙을 이유로 URL이나 인용문 원문을 다시 쓰지 않는다.
