## Overview

이 문서는 frontmatter에 기록하는 속성의 이름·자료형·허용값·관계·작성 규칙의 SSOT다.

- **다루는 것**
	- `type`, `tags`, 날짜, provenance를 포함한 속성 스키마
	- 태그는 별도 축이 아니라 속성 중 하나다.
- **다른 문서가 다루는 것**
	- 물리적 배치는 [[01. Folders and Placement]], 관계 선택은 [[16. MOC]]
	- 쓰기 권한은 [[03. Agent Permissions and Workflows]]
	- 도구와 템플릿은 [[04. Applications and Integrations]]와 [[15. Templates]], 본문 표현은 [[05. Writing Style]]
- **작성 기준**
	- [[00. Guideline Authoring]]과 [[guideline.template]]을 따른다.
	- 속성의 의미와 허용값은 이 사용자 정책에서 정하고, OMS는 실제 JSON 제어 파일을 사용한다.

```text
Properties
├── Core Fields — aliases(선택), tags, type, date_created, date_modified
├── Conditional Status — type-specific workflow field; Project/Area hub 금지
├── Authorship — type, created_by(user|agent), authorship(user|agent|mixed)
├── Agent Session Identity — optional session_id field ownership
├── Hermes Profile Identity — optional hermes_profile field ownership
├── Type Map — 43종 허용값 + 위치 + 분류 결정 절차
├── Navigation / Content / 85 Raw / Type-specific / Publishing / Metadata Fields
├── Tag System — format, category, hierarchy, assignment, cleanup
├── Markdown Syntax Pointer — authored-note 본문 표현은 [[05. Writing Style]] 참조
├── 날짜 링크 — 본문 wikilink vs frontmatter plain date
└── Property 정비 — 개명 마이그레이션 + 삭제(사용 금지) 목록
```

## Map

### Core Fields

`aliases`는 선택이며, 나머지 필드는 모든 노트에 포함한다.

| Property | Type | Rule | Example |
|---|---|---|---|
| `aliases` | list | 선택. 별칭이 있을 때만 포함 | `aliases: [AI]` |
| `tags` | list | 소문자 kebab-case. nested tag 는 `/` 구분 | `tags: [reference/article]` |
| `type` | text | Type Map 참고 | `type: article` |
| `date_created` | date | ISO 8601. linter 자동 관리 | `2026-04-03` |
| `date_modified` | date | ISO 8601. linter 자동 관리 | `2026-04-03` |

**Status values** — type-specific/conditional workflow field다.

- 진행 상태 추적이 의미 있는 유형에만 사용한다.
	- 필수: `task`/`book`/`paper`/`guide`/`draft`/`review`
	- 선택: 그 외
- 값: `todo`/`inprogress`/`done`/`reviewed`/`stop`
	- 소문자, 공백 없이 붙여 쓴다.
- Project/Area hub schema는 `status`를 제외한다.
	- 대상: `15. Work/01 Project/<name>/<name>.md`, `15. Work/02 Area/<name>/<name>.md`
	- `01 Project`/`02 Area` 폴더 배치가 active 상태를 나타낸다.

### Authorship

`CORE_KEYS = (type, created_by, authorship)`.

| Property | Values | Rule |
|---|---|---|
| `created_by` | `user` \| `agent` (literal string, 2-value) | 노트를 누가 만들었는지. wikilink 아님 |
| `authorship` | `user` \| `agent` \| `mixed` (literal string, 3-value) | 노트 저작 성격. `mixed`는 folder zone과 무관하게 user-created 노트에 agent 기여가 반영된 상태 |

- `created_by`/`authorship` 은 모든 노트에 존재해야 하는 core field 다.
- 유효한 `created_by`는 보존한다.
	- 생성 주체를 기록하므로 이후 edit에서도 바뀌지 않는다.
- 기존 사용자 작성 노트를 수정하려면 exact path 또는 deterministic manifest 승인이 필요하다.
- `created_by`가 없거나 허용값이 아니면 신원을 추정·기입하지 않고 검토 대상으로 둔다.
- `created_by` 허용값은 반드시 `user` 또는 `agent`다.
	- `unknown` 류 값은 사용하지 않는다.
- 승인된 agent edit가 user-authored 노트에 반영될 때 `created_by: user`를 유지하고 `authorship: mixed`로 전환한다.
- `authorship: mixed`는 agent 참여를 기록한다.
	- 이후 agent edit도 `created_by: user` 신호에 따라 다시 승인을 요구한다.
- `.oms/taxonomy.json`은 사용자 소유 폴더 taxonomy를 기록하며 existing-note ownership 신호가 아니다.
	- zone/new-file authority는 [[03. Agent Permissions and Workflows]]를 따른다.

### Agent Session Identity

`session_id`는 세션 보고서에 기록하는 선택적 문자열이다. 획득과 보고서 검색 절차는 [[03. Agent Permissions and Workflows#Agent Work Records]]가 담당한다.

- 상위 런타임이 제공한 실제 식별자를 따옴표로 감싸 원형 그대로 기록한다.
	- 형식 예시는 `session_id: "runtime-issued-id"`다.
	- UUID를 임의 생성하거나 터미널·전송 채널·모델 제공자·하위 에이전트의 식별자로 대체하지 않는다.
	- 신뢰할 수 있는 값이 없으면 필드를 생략한다.
- 세션 보고서에는 하나의 `session_id`를 두고 갱신할 때 보존한다.
	- 런타임이 식별자를 바꾼 경우에는 세션의 연속성을 확인하기 전까지 기존 값을 덮어쓰지 않는다.
- 기존 기계 영수증의 `session_id`를 이 규칙만으로 재해석하거나 일괄 변경하지 않는다.
	- `agent` 속성을 새로 만들거나 별도 보고서 타입을 추가하지 않는다.

### Hermes Profile Identity

`hermes_profile`은 채택자가 Hermes를 런타임으로 쓸 때, 런타임/호스트가 확인한 활성 Hermes 프로필의 정확하고 안정적인 이름 또는 ID를 담는 선택적 plain string이다.

- 확인된 값을 아는 Hermes 보고서에만 기록한다.
	- 예시 `hermes_profile: example-profile`는 형식 예시일 뿐 현재 프로필 식별자가 아니다.
	- 폴더, 호스트 이름, 이전 세션, persona prose 또는 다른 프로필에서 추론하지 않는다.
- 값이 확인되지 않으면 필드를 생략하고 사용자에게 확인을 요청한다.
	- Hermes가 아닌 실행에는 필드를 생략한다.
- 정적 프로필 목록이나 role registry를 만들지 않는다.
	- live profile roles/config는 사용자의 integration이 관리하며 frontmatter에 복사하지 않는다.
- `created_by`/`authorship`은 그대로 두며, 이 필드는 authorship classification이 아닌 execution context를 식별한다.
- 여러 세션이 같은 프로필을 공유할 수 있다.
	- `hermes_profile`로 `session_id`를 대체하지 않는다.
	- 프로필이 같다는 이유만으로 다른 세션의 보고서를 재사용하지 않는다.
	- 프로필별 분류는 보고서의 세션 단위를 변경하지 않는다.

#### Type 분류 결정 절차 (우선순위 순서, 상위 적용 시 하위 미검토)

1. **시간 캐덴스 파일명 패턴** — `YYYY-MM-DD`/`YYYY-Www`/`YYYY-MM`/`YYYY`/`YYYY-QN` → 해당 time type. 단 `15. Work/` 내부의 날짜 접두사 파일명은 ②의 `log` 규칙이 우선.
2. **System/Ops 폴더 규칙** — `15. Work/01·02·03` subfolder 안: `<폴더명>.md`→`project`, 날짜 접두사→`log`, `node:` 있는 설계 문서→`guide`, 그 외→`note`.
3. **엔티티 컬렉션 폴더** — `70. Collections` 하위 people/organization/places/church/channel/flower → 해당 엔티티 type; `08 Github`의 software catalog → `tool`.
4. **콘텐츠 포맷** — 원본 매체 형식에 따라 `article`/`book`/`paper`/`video`/`repo`/`tool`.
5. **Fallback** — 위 어디에도 해당 없으면 `note`. `00. Inbox` 안이면 `idea`.

### People — Discord 식별자와 프로필 링크

- 사용자 요청으로 확인한 Discord 계정은 `discord_user_id`에 변경되지 않는 숫자 사용자 ID를 **따옴표로 감싼 문자열**로 저장한다.
	- 표시 이름·사용자명은 바뀔 수 있으므로 ID로 대체하거나 동명이인 판정의 단독 근거로 삼지 않는다.
- ID는 선행 0 없이, 0보다 크고 `18446744073709551615` 이하인 십진 정수 문자열이어야 한다.
	- 형식 검사는 실제 계정 존재나 대상 인물 일치를 증명하지 않는다.
	- 사용자 제공 근거 또는 권한 있는 프로필 확인으로 대상 인물을 검증한다.
- `discord`는 검증한 ID에서 만든 `https://discord.com/users/<discord_user_id>`만 사용한다.
	- 본문에는 이 주소를 `[Discord 프로필 열기](...)` 링크로 표시한다.
	- 링크 열람은 Discord 로그인과 접근 권한에 따라 달라지며 공개 프로필 조회를 보장하지 않는다.
- 확인되지 않은 ID와 링크는 비워 둔다.
	- 로그인·MFA·권한 제한, 동명이인 또는 식별자 충돌에서는 추측하거나 다른 계정으로 넘어가지 않는다.
	- 사용자 요청 범위의 검증된 필드만 부분 반영한다.
- 근거에는 사용자 제공·주소록·개인 대화 요약·인증된 Discord·공개 웹을 구분한다.
	- 실제 ID·연락처·비공개 메시지를 실행 로그, 테스트, 이슈, 커밋에 복사하지 않는다.
	- 사용자 원본 노트의 `created_by: user`는 유지하고 승인된 에이전트 수정은 `authorship: mixed`로 기록한다.

### 본문 표현은 Writing Style 참조

직접 작성한 본문의 구조와 Markdown 표현은 [[05. Writing Style]]을 따른다. 이 문서에서는 아래 날짜 링크 계약만 관리한다.

### 날짜 링크

본문에서 날짜를 언급할 때는 plain text 가 아니라 Time 노트 wikilink 로 쓴다.

- 날짜별 백링크가 쌓여 해당 Time 노트에서 그날 무슨 일이 있었는지 역추적된다.
- 이 날짜 링크 규칙은 직접 작성한 본문에만 적용한다.
	- 원문 인용·캡처 본문·코드·URL의 날짜 표기는 원문 그대로 두고 바꾸지 않는다.

| 단위 | 형식 | 대상 폴더 | 예 |
|---|---|---|---|
| 일 (기본) | `[[YYYY-MM-DD]]` | `10. Time/01 Daily Notes/` | `[[2026-09-17]]` |
| 주 | `[[YYYY-nnW]]` | `10. Time/02 Weekly Notes/` | `[[2026-38W]]` |
| 월 | `[[YYYY-MM]]` | `10. Time/03 Monthly Notes/` | `[[2026-09]]` |
| 분기 | `[[YYYY-Qn]]` | `10. Time/05 Quarterly Notes/` | `[[2026-Q3]]` |
| 연 | `[[YYYY]]` | `10. Time/04 Yearly Notes/` | `[[2026]]` |

- 기본값은 일 단위 `[[YYYY-MM-DD]]` 다.
	- 일정·이벤트·기록 시점을 본문에 적을 때 그대로 링크한다.
- 기간은 양끝을 각각 링크한다 — `[[2026-09-18]] ~ [[2026-09-19]]`.
- 대상 Time 노트가 아직 없어도 링크한다.
	- 미래 날짜가 열릴 때 백링크가 이미 붙어 있는 것이 의도된 동작이다.
- **frontmatter 날짜 필드는 링크로 감싸지 않는다.**
	- `date_created`·`date_modified`·`due`·`plan`·`date_meet`·`date_finished`·`date_started` 등은 ISO 8601 plain date 로 유지한다.
	- Bases·Dataview 가 문자열이 아니라 date 로 읽어야 정렬·비교가 동작한다(아래 `Wikilink 값 사용 제한` 참고).
- 파일명 prefix 의 날짜(`YYYY-MM-DD <name>.md`) 도 링크가 아니다.
- heading 안에는 날짜 링크를 넣지 않는다.
	- heading anchor(`[[note#...]]`) 가 깨진다.
	- 날짜가 제목에 들어가면 heading 은 plain 으로 두고 바로 아래 본문·표에서 링크한다.

### Tag System

**Format**: 소문자, kebab-case, `/` 계층 구분, 영어 전용(한국어 태그 금지).

| Category | Tags | 사용처 |
|---|---|---|
| Content type | `reference`, `reference/article`, `reference/video`, `reference/paper` | 콘텐츠 유형 |
| System | `guideline`, `template` | 시스템 노트 |
| Agent | `claude`, `codex`, `gemini`, `openclaw` | 에이전트 식별 |
| Date | `YYYY/MM` | 생성 시기 |

**이 볼트 전용**

- Domain tags: `programming`, `programming/backend`, `pkm`, `faith`, `faith/bible`, `sound`, `health`, `finance`, `ai`, `productivity`, `music` 등. `moc:` 필드와 함께 사용한다.
- Note Class tags: `literature`, `permanent`, `fleeting`, `prompt`
- Content Format tags: `reference/paper`, `reference/book`, `reference/video`, `reference/article`, `collection/terminology`, `collection/person`, `collection/place`
- Project/Area tags: `project`, `area`, `trip`, `archive`
- Periodic tags: `daily`/`weekly`/`monthly`/`quarterly`/`yearly`

**Hierarchy**

- 부모+자식 동시 부여 금지(자식만 사용).
- 도메인 태그 최대 2개.
- `reference/*` 는 `type:` 과 일치.

**Assignment**

- 최소 1개 태그 필수.
- 시스템 노트(`guideline`/`template`)는 도메인 태그 미추가.
- Periodic Note 는 주기 태그 1개만.
- Agent 태그는 `created_by: agent` 일 때 부여한다.
	- 구체적 agent 식별자(`claude`/`codex`/`gemini`/`openclaw` 등)의 판단 근거는 [[03. Agent Permissions and Workflows#Provenance Signal]]이 SSOT 다.

**Review**

- 사용 빈도 3건 미만의 고유 태그는 정기 검토한다.
- 변경 전 의미와 사용처를 확인한다.

### OMS JSON Cross-ref

- 속성의 의미와 허용값은 이 사용자 정책이 정한다.
- 사용자 소유 OMS 제어 파일은 `.oms/template-policy.json`과 `.oms/taxonomy.json`이다.
	- `.oms/template-policy.json`은 템플릿·필드 선언을 기록한다.
	- `.oms/taxonomy.json`은 폴더 의미와 템플릿 라우팅을 기록한다.
- `.obsidian/types.json`은 Obsidian이 관측한 property type 상태를 읽기 전용으로 제공한다.
- `.oms/types.json`은 위 입력과 템플릿에서 생성된 파생물이며 속성 의미의 정본이 아니다.
- 관측·파생 파일에 명시되지 않았다는 이유만으로 property 제약을 추가하거나 기존 property를 삭제하지 않는다.
	- 예를 들어 이 정책이 허용하는 `cover_url`은 그대로 보존한다.

## Rules

- Indent 2-space(탭 금지). Property key 는 snake_case, 소문자, 영어만.
- Wikilink 값은 YAML 에서 반드시 따옴표로 감싼다.
- 특수문자(`:`, `#` 등) 포함 값은 따옴표로 감싼다.
	- 예: `description: "Extract: content"`.
- 날짜는 ISO 8601(`YYYY-MM-DD`), 날짜 필드는 `date_` prefix. Boolean 은 `true`/`false`.
- `created_by`/`authorship`은 리터럴만 사용한다.
	- `created_by`: `user`\|`agent`
	- `authorship`: `user`\|`agent`\|`mixed`
	- 유효한 `created_by`는 보존한다.
	- 승인된 user-authored note edit는 `created_by: user`를 유지하고 `authorship: mixed`로 전환한다.
	- 부재·비허용 값은 신원을 만들지 않고 검토한다.
- Wikilink 사용 가능 property 는 명시된 것만.
	- Navigation: `up`,`moc`,`index`,`project`,`related`,`referenced`,`review`
	- Content: `author`,`source`
	- Type-specific: `church`,`speaker`,`participants`,`proposer`,`week`,`month`,`year`,`quarter`,`roundup`,`meeting`,`book`,`superseded_by`
	- 그 외 property 는 plain string/date — wikilink 금지.
- 태그는 소문자 kebab-case, 영어 전용, 부모·자식 동시 부여 금지, 도메인 최대 2개, `reference/*` 는 `type:` 과 일치, 최소 1개 부여.
- `moc` 값의 선택·개수·축 조합은 [[16. MOC]]를 따른다. 이 문서는 필드 인코딩만 담당한다.

	- 폴더 배치 충돌은 [[01. Folders and Placement]]에 양보한다.
	- [[03. Agent Permissions and Workflows]]와 공유 tier-4 [[04. Applications and Integrations]]·[[15. Templates]]보다 우선한다.

### `project` Vs `log` Vs `note` — 같은 폴더, 다른 Type

`15. Work/01 Project/`·`02 Area/` subfolder 안이라고 전부 `project` 가 아니다.

- `<폴더명>.md` → `project`
- `YYYY-MM-DD <이름>.md` → `log`
- 그 외 → `note`(fallback)

### Wikilink 값 사용 제한

내용이 비어 있는 wikilink(겹대괄호만 있고 노트명이 없는 형태)는 어떤 property 에도 사용하지 않는다. plain string/date 필드(`type`, `date_modified` 등)에 wikilink 형식 값을 넣지 않는다.

### `music` 허용값 — 소문자 고정

`music: CCM`(x) → `music: ccm`(o). 목록 외 값 금지. 값은 태그와 같은 소문자 kebab-case 를 쓴다(`hip-hop`·`rnb`). 대소문자만 다른 값은 Bases 필터에서 서로 다른 값으로 취급되므로 표기를 섞지 않는다. `국악`은 대소문자가 없어 그대로 둔다.

### 부모·자식 태그 중복 / `type` 불일치

`tags: [reference, reference/article]` 처럼 부모+자식을 함께 쓰면 Tag Pane 에서 중복 집계된다. `type: article` 인데 `tags: [reference/video]` 처럼 불일치하면 Bases 쿼리가 잘못 분류한다 — 항상 일치시킨다.
