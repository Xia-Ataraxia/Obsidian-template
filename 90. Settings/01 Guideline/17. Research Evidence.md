## Overview

이 문서는 조사 결과를 볼트에 남길 때 그 근거를 얼마나 믿을 수 있는지 판정하는 기준의 SSOT다. 같은 문장이라도 어디에 실렸고 얼마나 인용됐는지에 따라 무게가 다르며, 그 차이를 노트에 드러내는 것이 목적이다.

- **다루는 것**
	- 근거 등급과 등급별 사용 범위
	- 게재처·피인용 확인 절차와 arXiv 전용 자료의 취급
	- 제품 적용을 판단할 때 필요한 production 근거의 별도 수집
	- Zotero 입력 전 논문 초안 노트의 citation key 규칙
- **다른 문서가 다루는 것**
	- 논문 노트의 물리적 배치는 [[01. Folders and Placement]], 필드 정의는 [[02. Properties]]
	- 쓰기 권한과 workflow 선택은 [[03. Agent Permissions and Workflows]]
	- Zotero·ZotLit 역할과 식별자 연결은 [[04. Applications and Integrations]]
	- 본문 표현과 링크 표기는 [[05. Writing Style]], 템플릿 실행은 [[15. Templates]]
	- 원문에서 wiki·용어 노트를 만드는 절차는 [[06. Knowledge Compile Guideline]]
- **출처**
	- 과학적 근거(scientific justification) 선호를 실행 규칙으로 구체화했다.
- **작성 기준**
	- [[00. Guideline Authoring]] 과 [[guideline.template]] 을 따른다.

```text
Research Evidence
├── Evidence Grade — A/B/C/D 와 등급별 사용 범위
├── Venue and Citation Check — 게재처·피인용 확인 절차
├── arXiv Downgrade — 학회 게재 없는 preprint 취급
├── Production Evidence — 학계 근거와 분리해 따로 모으는 축
├── Citation Key — 출판 연도 기준 citekey 규칙
└── Recording Evidence — 노트에 등급을 드러내는 방법
```

## Map

### Evidence Grade

조사 결과를 노트에 쓸 때는 근거마다 등급을 판정한다. 등급이 다른 근거를 한 문장에 섞지 않는다.

| 등급 | 조건 | 사용 범위 |
|---|---|---|
| A | 피어리뷰 게재 + 피인용 확인 | 결정의 1차 근거로 쓴다 |
| B | 피어리뷰 게재이나 최신이라 피인용이 없거나 적음 | 방향 근거로만 쓴다. 확증으로 제시하지 않는다 |
| C | arXiv 등 preprint 전용, 학회·저널 게재 없음 | 엔지니어링 참고로만 쓴다. 성능·효과 주장의 근거로 쓰지 않는다 |
| D | 사내 단일 측정, 재현 절차 미확보 | 현상 유지 근거로만 쓴다. 변경이나 승격의 근거로 쓰지 않는다 |

- 결정을 바꾸는 주장에는 A 등급 근거를 요구한다.
	- A 등급이 없으면 결정을 미루고 무엇을 측정해야 하는지 적는다.
- B 등급만으로 세운 주장은 문장 안에서 그 사실을 밝힌다.
	- 예: 게재는 됐으나 피인용이 없어 확증이 아니라 방향 근거다.
- D 등급 수치를 표에 넣을 때는 seed 수와 측정 조건을 함께 적는다.

### Venue and Citation Check

- **게재처와 피인용은 추정하지 않고 조회해서 확인한다.**
	- arXiv 초록 페이지의 저자 comment 는 게재 표기의 1차 단서이지 확정이 아니다.
	- 확정은 게재처 기록이 있는 서지 API 로 한다.
- 조회에는 OpenAlex 를 기본으로 쓴다.
	- 제목 검색은 preprint 레코드와 게재본 레코드를 함께 반환한다. **게재본 레코드의 피인용 수를 쓴다.**
	- preprint 레코드만 보고 피인용이 적다고 판단하지 않는다. 같은 논문이 두 레코드로 나뉘어 집계된다.
- Semantic Scholar 는 보조로 쓴다.
	- 짧은 시간에 반복 호출하면 차단된다. 한 건씩 확인할 때만 쓴다.
- 확인한 값은 조회한 날짜와 함께 적는다.
	- 피인용 수는 시간이 지나면 바뀐다. 날짜 없는 수치는 검증 불가능한 기록이다.

### arXiv Downgrade

- **arXiv 에만 있는 자료는 C 등급이다.**
	- 피인용이 많아도 학회·저널 게재가 확인되지 않으면 등급을 올리지 않는다.
	- 기술 리포트, 시스템 설명, 벤치마크 수치는 구현 참고로 쓸 수 있다.
	- 방법의 우월성이나 성능 비교 결론의 근거로는 쓰지 않는다.
- 같은 논문의 게재본이 확인되면 등급을 A 또는 B 로 올리고 노트의 연도·게재처를 함께 고친다.

### Production Evidence

- **학계 근거와 production 근거는 다른 축이며 따로 모은다.**
	- 논문은 무엇이 가능한지를 말하고, production 자료는 실제로 무엇을 감당하는지를 말한다.
	- 둘 중 하나만으로 제품 결정을 내리지 않는다.
- production 근거에는 출처의 성격을 함께 적는다.
	- 공식 문서, 표준·인증 기준, 벤더 발표, 현장 측정은 신뢰도가 다르다.
	- 벤더가 발표한 성능 수치는 독립 검증이 아님을 문장에 밝힌다.
- 측정 단위를 제품 운영의 단위로 바꿔 적는다.
	- 정확도 하나로 요약하지 않고 운영이 실제로 부담하는 단위를 쓴다.

### Citation Key

- **Zotero 에 넣기 전에도 논문 노트를 citation key 로 먼저 만들 수 있다.**
	- 노트의 배치는 [[01. Folders and Placement]], 필드는 [[02. Properties]] 를 따른다.
- **파일명, `citekey` 필드, 본문의 `**Citekey**::` 세 곳을 CamelCase 로 맞춘다.**
	- 예: `Wang2024Planning.md` / `citekey: Wang2024Planning` / `**Citekey**:: @Wang2024Planning`
	- 2025년 가을까지 import 된 노트는 `citekey` 필드만 소문자다. 이전 템플릿의 흔적이며 현행 규칙이 아니다.
	- 기존 노트를 일괄 개명하지 않는다. 그 노트를 다시 손대는 작업에서만 맞춘다.
- 구성 요소는 `{제1저자 성}{출판 연도}{제목 첫 실단어}` 다.
	- 제목 단어를 줄이지 않고 통째로 쓴다. 과거 import 에 남은 `Vaswani2017Atten` 같은 5글자 절단형은 현행 규칙이 아니다.
	- 하이픈·콜론·어포스트로피 같은 기호는 지우고 붙인다. `Commit-Level` 은 `CommitLevel` 이다.
	- 관사는 첫 실단어로 세지 않는다. `A Survey on ...` 은 `Survey`, `An Empirical Study ...` 는 `Empirical` 이다.
	- **연도는 출판 연도다.** arXiv 최초 게재 연도가 아니다.
	- 게재본이 확인되지 않으면 preprint 연도를 쓰고, 나중에 게재가 확인되면 파일명과 필드를 함께 고친다.
- **파일명을 바꿀 때는 macOS 의 case-insensitive 파일시스템을 주의한다.**
	- `core.ignorecase` 가 `true` 면 대소문자만 바뀜 이름을 git 이 같은 경로로 본다.
	- 임시 이름을 거쳐 `git mv` 를 두 번 실행하고, 한 번에 하나씩 확인한다.
- 본문 형식은 기존 ZotLit import 노트를 정본으로 삼는다.
	- 임의의 섹션 구조를 새로 만들지 않는다.
	- Zotero 가 채우는 필드는 import 전까지 비워 둔다. 값을 지어내지 않는다.

### Recording Evidence

- **등급은 노트 안에서 보이게 적는다.**
	- 근거를 나열한 표에는 게재처, 피인용 수, 등급을 함께 둔다.
	- 결정 노트에서는 어떤 등급의 근거로 그 결정을 했는지 문장에 드러낸다.
- 확인하지 못한 항목은 비워 두거나 확인 실패로 적는다.
	- 값을 채우려고 추정하지 않는다.
- 별도의 검증 완료 필드를 만들지 않는다.
	- 게재처와 피인용이 기록돼 있으면 그 자체가 확인의 결과다.
	- 필드가 하나 늘면 그 필드를 신뢰할 수 있는지 다시 관리해야 한다.

## Rules

- 근거마다 A/B/C/D 등급을 판정하고, 등급이 다른 근거를 한 문장에 섞지 않는다.
- 게재처와 피인용은 조회해서 확인하고, 조회한 날짜를 함께 적는다.
- 게재본 레코드의 피인용 수를 쓴다. preprint 레코드의 수치로 판단하지 않는다.
- arXiv 전용 자료는 C 등급이며 성능·효과 주장의 근거로 쓰지 않는다.
- 결정을 바꾸는 주장에는 A 등급 근거를 요구하고, 없으면 결정을 미루고 측정 항목을 적는다.
- 학계 근거와 production 근거를 따로 모으고, 벤더 발표는 독립 검증이 아님을 밝힌다.
- 파일명·`citekey`·`**Citekey**::` 세 곳을 CamelCase 로 맞춘다. 제목 단어를 줄이지 않고 연도는 출판 연도를 쓴다.
- 새 노트를 만들기 전에 같은 논문의 기존 노트를 먼저 찾는다.
- 파일명 규칙을 바꾸기 전에 기존 노트에서 실제 표기를 먼저 관찰한다. 다수가 따르는 표기가 현행 규칙이다.
- 검증 완료를 표시하는 별도 필드를 만들지 않는다.

## Caveats

### 피인용 수를 품질과 혼동하지 않는다

피인용은 그 주장이 학계에서 검토됐다는 신호이지 옳다는 증명이 아니다. 최신 논문은 좋아도 인용이 없고, 오래된 논문은 반박됐어도 인용이 많다. 등급은 검토 여부를 나누는 도구이지 참과 거짓을 나누는 도구가 아니다.

### 등급이 낮다고 버리지 않는다

C 나 D 등급 자료를 노트에서 지우지 않는다. 등급을 적어 두고 쓰임을 제한한다. 사내 측정은 D 등급이지만 우리 환경에서만 얻을 수 있는 유일한 값인 경우가 많다.

### 모두 같은 이름이 아니면 중복 사본을 의심한다

파일명 뒤에 ` 1` 이 붙은 노트는 동기화 충돌 사본이지 별도 문헌이 아니다. 이때 나중에 들어온 쪽이 더 완전한 경우가 있으므로, 이름만 보고 원본을 남기지 말고 두 파일의 내용과 날짜를 모두 읽고 합친다.

### 이 문서는 조사 절차를 정의하지 않는다

무엇을 믿을 수 있는지가 이 문서의 범위다. 어떤 도구로 어떻게 조회하는지의 재사용 절차는 skill 저장소가 담당한다. 경계는 [[03. Agent Permissions and Workflows#Skill Package]] 를 따른다.
